Library calls inside an effect (issue #31)

An effect re-runs when a signal it read changes, including the signals a library call read on its behalf. So the call itself shouldn't read any: the effect should depend only on what it reads itself. Each card is an effect from an app, shown without the demo's run counter. After each action its numbers should match the expected ones. The fake server answers in {{ latency }} ms (no network), and the demo stops an effect after {{ runLimit }} runs, so a loop can't run away.

What to try

Every action should match the expected numbers. What each card does before the fix:

  • Prefetch the next page — each response re-runs the effect, which requests the page again: a request every {{ latency }} ms until the demo stops the effect.
  • Refetch when back online — each refetch re-runs the effect at once, which cancels it and sends another, until the demo stops the effect.
  • Refetch on a server push — the push itself refetches once, as it should. After it, every new entry in the cache re-runs the effect and refetches the list again: open a todo, or click through another card.
  • Auto-save with an optimistic update — one keystroke saves until the demo stops the effect: the update re-runs the effect, which saves and updates again.
  • Auto-save, then open another note — type, then open the other note: the effect re-runs and saves the draft into the note you just opened.
  • Either auto-save card, typed fast — a save that lands while the next one is in flight re-runs the effect, which saves again: a save every {{ latency }} ms until the demo stops the effect.

To see a change in the library here, rebuild it with pnpm build:lib or keep pnpm watch running: the playground uses the build in dist
