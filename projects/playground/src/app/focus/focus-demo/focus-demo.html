Refetch on window focus and reconnect (issue #28)

Coming back to the tab, or getting the network back, should refetch the queries on screen whose data is stale: once per query, however many components show it, and a request already in flight is kept rather than sent again. What to try

After each event the requests should match the expected ones. What each event does before the feature:

  • Leave the tab and come back — the defaults, the 'always' row and the three components should send one request each, and the other rows none. Nothing is sent.
  • The same a minute later — the data of the staleTime: 60_000 row is stale by then, so it should send a request too. It doesn't.
  • Go offline and back online — should do what coming back to the tab does. Nothing is sent.
  • Both at once , as when a laptop wakes up — still one request per row: the second event finds the first one's request in flight. Nothing is sent.
