What to try
  • Load more, a few times — a page each time, asked for from the id after the last todo shown.
  • Load 3 pages, then Delete the first todo — the list fetches its 3 pages again: from id 1, then from the id after each page's last todo, which moved by one. Asking for the cursors the pages were fetched with would show a todo twice.
  • Load 3 pages, then Save a todo — all 3 pages come again in the next version, one after the other; the list stays 3 pages long.
  • Load more, and Save while the page loads — the refetch replaces the page in flight: the list fetches the pages it held, and the new page isn't added. Load more again once it's in.
  • Load on scroll on, Save, then scroll to the end — while the refetch runs, nothing is added; once it's in, the next page comes on its own: the effect runs again as isFetching() goes false.
  • maxPages 3, then Load more 3 times — the first pages go as new ones come; Load previous brings them back. Load 5 pages first, then turn maxPages on: the next page leaves 3.
  • Load 3 pages, Save, then switch to "done" at once — with an Observable queryFn , the refetch of the list you left is cancelled: its pages stay, and it refetches when you switch back. With a Promise one, nothing stops it: the page in flight lands, and no page is asked for with the next filter, so the list you left keeps the page that came before the switch, all of it "all". Switch back to see it.
  • Fail the next request, then Load more — the list keeps its pages and says the next page failed; Load more tries it again.
