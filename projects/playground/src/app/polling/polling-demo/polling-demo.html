What to try

Start with one setting changed at a time. What each one does before the fix, and what it should do:

  • defaults (1 observer, {{ interval }} , noise off) — polls {{ interval - latency }} ms after each response: the timer ticks every second, however long the request took. Should be {{ interval }} ms.
  • noise every 300 ms — no polls at all, and "since the last response" keeps growing: every change restarts the timer before it fires. Should make no difference.
  • noise every 1.5 s — polls follow the noise, {{ interval / 1000 }} s after each change rather than after the response.
  • injectQueries · noise every 300 ms — the same stall, although only the neighbour query reads the noise.
  • ({{ '{' }} state {{ '}' }}) => {{ interval }} — unlike the number, polls about {{ interval }} ms after each response, give or take change detection. Both forms should behave the same.
  • 3 observers — three timers out of step, a request every third of a second. Should be one request per interval.
  • invalidateQueries in the middle of an interval — the next poll keeps its slot, often right after the refetch. It should come {{ interval }} ms after the refetch's response.
  • Infinity — requests back to back: the browser takes the delay as 0. Should not poll at all.
