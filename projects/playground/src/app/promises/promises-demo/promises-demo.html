What to look at
  • Add · waits for the list — the button stays disabled until the new todo is in the list: the mutation finishes once the refetch its onSuccess returns has landed.
  • Add · doesn't wait — the same call in braces returns nothing: the button comes back as the write lands, and the list catches up {{ listLatency }} ms later.
  • Add · mutateAsync — the code after await runs once the list is fresh. With next write fails , the failure lands in catch .
  • Refresh — resumes with the list's data and error . With next list load fails , it still resolves: the old todos, and the error.
