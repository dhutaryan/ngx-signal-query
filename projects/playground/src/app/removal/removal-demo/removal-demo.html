removeQueries while a component shows the key (issue #37)

A component looks its query up in the cache when its options change, and only then. removeQueries drops the query from the cache but leaves the options alone, so a component showing the key keeps watching the dropped query. Whatever goes through the cache by key afterwards — a refetch, a write, an invalidation, another component, a poll — lands in a new entry that component doesn't watch.

Right after the removal a component may keep what it shows: nothing puts the key back on its own, as in TanStack. Once something does, every component on the key should show what the cache holds, so that's what expected says; red marks a component that shows something else. The fake server answers in {{ latency }} ms (no network), each time with a new version.

What to try

What each card does before the fix:

  • Reset, then edit — press removeQueries , then refetch() : list A stays on its version while the cache holds the new one. setQueryData : the cache holds the edit, list A doesn't. invalidateQueries : no request, because no component watches the cache's entry. Mount list B: it shows what the cache holds, list A doesn't.
  • Polling widget — start it, then press removeQueries : widget A keeps polling, but into the query the cache dropped, so its version climbs while the cache stays empty. Mount widget B: two polls per interval, and the widgets show different versions.
